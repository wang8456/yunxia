# 云匣 App 实现路径（第二版 · FastAPI）

> **For Hermes:** 按本文件逐阶段执行；每阶段结束跑验收表，不通过不进入下一阶段。

**目标：** 把云匣从「dufs 网页」变成多端应用：安卓（手机+平板）先行，Web 端换 Vue 3 + TS，
所有端只经一个 FastAPI 服务（统一 API + WebSocket）取数与实时同步。

**架构：** 单入口 5007 → 前置分流 → ①FastAPI（控制面：认证/目录/搜索/进度/任务/WS）②dufs（数据面：文件字节与 Range）。
FastAPI 不搬运大文件，只发指令；文件读写仍由 dufs 直接对外。

**技术栈：** FastAPI + uvicorn + SQLModel/aiosqlite + watchdog（NAS 原生 venv）｜Flutter 3.x + Riverpod + go_router + dio + video_player｜Vue 3 + TS + Vite + Pinia + TanStack Query

## P1 契约与认证

### Task 1.1 口令登录换设备令牌
```python
# app/routers/auth.py
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel
router = APIRouter()

class LoginIn(BaseModel):
    password: str
    device: str = "unknown"

@router.post("/auth/login")
def login(body: LoginIn):
    if not verify_password(body.password):        # 与云匣现有口令一致，只存哈希
        raise HTTPException(401, "口令不对")
    token = make_jwt(device=body.device, days=30)
    return {"token": token, "expires_in": 30 * 86400}
```
**验收（pytest）：**
```python
def test_login_ok(client):  assert client.post("/api/v1/auth/login", json={"password": PW}).status_code == 200
def test_login_bad(client): assert client.post("/api/v1/auth/login", json={"password": "x"}).status_code == 401
def test_fs_needs_token(client): assert client.get("/api/v1/fs/list?source=nas&path=/").status_code == 401
```

### Task 1.2 契约即代码

- Web：`npx openapi-typescript http://127.0.0.1:15100/openapi.json -o web/src/api/schema.d.ts`

## P2 文件域 API（控制面）

### Task 2.1 统一模型
```python
class FileEntry(BaseModel):
    name: str
    path: str            # 源内绝对路径，以 / 开头
    is_dir: bool
    size: int = 0
    mtime: float = 0.0
    kind: str = "file"   # file|dir|image|video|audio|text|archive
    url: str | None = None
```

### Task 2.2 dufs 适配器（沿用实测到的怪癖）
| 操作 | 正确做法 | 上一版踩的坑 |
|---|---|---|
| 列目录 | `GET {path}/?json`（路径必须带尾斜杠） | 不带尾斜杠返回 HTML |
| 建目录 | `MKCOL {path}` | `PUT dir/` 会建出 0 字节文件 |
| 上传 | `PUT {path}` **必须带 Content-Length** | chunked 会 411 |
| 改名/移动 | `MOVE` + `Destination` 用**绝对 URL** | 相对路径 400 |
| 删除 | `DELETE {path}` | — |
| 搜索 | 不存在，别试 | `?search`/`?q` 返回整页目录列表（看着像成功） |

### Task 2.3 下载直链（关键性能决策）
`GET /api/v1/fs/link?source=nas&path=/影片/x.mp4` → 返回带 HMAC 的 dufs 直链（5 分钟有效），客户端**直连 dufs 拿字节**。
- 实测基线：API 中转 14 MB/s，直连 dufs 34 MB/s。
- 不把大文件塞进 FastAPI：`StreamingResponse` 只用于小文件/缩略图。

**验收：** `curl -o /dev/null -w '%{speed_download}'` 直链 ≥ 25 MB/s；`Range` 请求返回 206、越界返回 416。

### Task 2.4 三源适配
`dufs`(NAS 15007) / `webdav`(115 via 5008) / `pcdufs`(两台电脑经 pcproxy 5010)。每个源实现同一组 6 个方法，`/api/v1/sources` 返回在线状态（HEAD 探活 2s 超时）。

**验收：** `GET /api/v1/sources` 里 nas=true、115=true、pc 至少一台 true；任一源失败不影响其它源（逐个 try/except）。

## P3 实时（WebSocket）

### Task 3.1 inotify → 事件
watchdog 监听 `/mnt/data/share` 六个一级目录，debounce 0.4s，事件入环形缓冲（200 条，带 `seq`）。

### Task 3.2 WS 端点
```python
@app.websocket("/ws")
async def ws(ws: WebSocket, t: str = Query(None), since: int = 0):
    dev = auth_ws(t)
    if not dev: await ws.close(code=4401); return
    await hub.add(ws, since=since)     # since>0 先补发缓冲里 seq>since 的事件
```
事件形状：`{"type":"fs.changed","source":"nas","path":"/下载","name":"a.mp4","op":"create|write|move|delete","is_dir":false,"seq":42}`，另有 `hello{seq}`、`ping/pong`（服务端 25s）。

**验收：** 脚本连 WS → SSH 到 NAS `touch` 一个文件 → 3 秒内收到 `create`；杀掉连接重连带 `since` → 收到补发；假 token → 4401。

### Task 3.3 客户端策略
Flutter/Vue 都只做一件事：收到 `fs.changed` 且 `path == 当前目录` → 局部刷新（不整页 reload）。断线指数退避 1s→30s。
